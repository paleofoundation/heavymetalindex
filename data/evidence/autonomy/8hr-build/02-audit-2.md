**Reviewer:** Claude (Opus 4.7), re-auditing both the original plan AND Audit 1.

## What Audit 1 caught well

- Daemon-load failure modes (Issue 1).
- OpenAlex rate limits + paywalled-paper reality (Issue 2).

## What Audit 1 missed

### Issue 8: The plan assumes the briefings regenerate cleanly with new pooled data

Each tick regenerates the 15 Cat 1 briefings. The briefing generator (`tools/standards/build-standards-briefing.mjs`) reads from `data/evidence/hmtc_aggregate_distributions.csv` and produces the briefing markdown. **If the pooled distribution changes structurally between ticks (new sources entering the pool change a clean/dirty classification), the briefing's prose can drift from the methodology in a way that lint catches but the daemon doesn't fix.** The regression tests on briefings (`tools/standards/build-standards-briefing.test.mjs`) guard against percentile inversion and phantom co-authors, but not against subtle drift in adversarial-read prose.

**Mitigation:** Add a step to the daemon: after briefings regenerate, run `npm test` on the briefing test suite. If tests fail, log loudly to the morning report and abort the commit for that tick (preserve the prior good state).

### Issue 9: Cat 5 pages don't have a briefing pipeline

The 15 Cat 1 briefings are generated by `tools/standards/build-standards-briefing.mjs`. The 16 Cat 5 product pages don't have an equivalent generator yet. The plan implicitly assumes Cat 5 will get the same treatment, but the tooling needed for Cat 5 (a Cat-5-aware briefing generator that uses the beverage-specific pooling cells) hasn't been written.

**Mitigation:** Either (a) extend the existing briefing generator to handle Cat 5 product slugs, (b) build a parallel `build-standards-briefing-cat5.mjs`, or (c) accept that Cat 5 closure means the master summary at `data/workbench/category-5-beverages-master.md` and the public product pages at `wiki/products/<cat5-slug>.md` get their tables filled, but no separate "Cat 5 briefings" directory is created. Option (c) is fine for tonight; (a) or (b) is a follow-up.

### Issue 10: The Cat 5 master is a workbench document, not a public-facing artifact

The `data/workbench/category-5-beverages-master.md` is staff-side per its frontmatter (`audience: [internal]`, `noindex: true`). It carries percentile arithmetic per the firewall. Closing Cat 5 cells means updating BOTH the workbench master AND the public-facing pages at `wiki/products/<cat5-slug>.md`, which carry the literature-native view without percentile arithmetic. These two updates are not yet linked by tooling.

**Mitigation:** Add to the daemon a step that, when a Cat 5 cell closes, regenerates both:
- The workbench master row in `data/workbench/category-5-beverages-master.md`
- The literature-native public page section at `wiki/products/<cat5-slug>.md`

This wiring doesn't exist yet. It's a tooling deliverable for the 8hr build itself.

### Issue 11: The plan doesn't address what happens to currently-failing ingest paths

The daemon attempts `node tools/autonomy/create-missing-pages.mjs`, `node tools/autonomy/firewall-lint.mjs`, and `node tools/autonomy/ingest-marker-batch.mjs`. All three are missing files. The daemon swallows the errors with `|| true`. So the daemon has been running for hours, producing failed-step log entries on every tick, and the morning report doesn't surface this clearly.

**Mitigation:** Build all three tools tonight as part of step 2. Until they exist, the daemon's autonomous-ingest claim is fiction. Until they exist, the 8hr build does no autonomous ingest. **This is the most critical mitigation in either audit.**

### Issue 12: Sonnet 4.6 cost may be higher than estimated

The estimate of $0.06/paper × 320 papers = $19 assumes short extraction. In practice, extracting a 30-page paper with figures and tables into structured frontmatter + body summary can run 5-10K input tokens and 2-3K output tokens. At Sonnet 4.6 prices (~$3/MTok input, ~$15/MTok output), that's roughly $0.05-0.08/paper. The estimate is in the right zone but could trend $25-35 instead of $19 if papers are long.

**Mitigation:** Set a hard daily cost ceiling in the ingest tool. If cumulative spend exceeds $50, the tool stops and surfaces in the morning report. Karen reviews and decides whether to raise the ceiling.

### Issue 13: No verification that papers are actually in `raw/markdown/` to ingest

The autonomous ingester reads from `raw/markdown/FM_*/*.md`. The Marker conversion pipeline produces these files. If no new papers are in `raw/markdown/` and the wishlist fetcher hasn't downloaded new PDFs (or Marker hasn't converted them), the ingester does nothing regardless of batch size. The plan assumes papers are available; reality may be that the queue is thin.

**Mitigation:** Before the 8hr window starts, verify `raw/markdown/` has at least 100-200 unprocessed papers (FM_ folders without corresponding `wiki/sources/` pages). If thin, run the Marker conversion pipeline on the wishlist-fetched PDFs first. (Marker conversion is itself a separate pipeline; checking its state is in scope.)

### Issue 14: The morning report assumes a daily cycle, not an 8hr window

The morning report is per-day. For an 8hr window that spans an arbitrary clock period (say, 8 PM tonight to 4 AM tomorrow), the morning report straddles two days. The hour-by-hour table in the plan assumes contiguous activity but the morning report doesn't naturally chunk by 8-hour blocks.

**Mitigation:** Write a separate `8hr-build/06-final-state-report.md` that the autonomous closeout step produces at t+8h, in addition to whatever the morning report accumulates. Use the daemon's existing log structure but add a "since 8hr build start" delta.

### Issue 15: The Florida entity vs Cyprus entity issue affects the manual but does NOT affect the daemon work tonight

This is a non-issue, but worth checking: the recent Cyprus → Florida correction to the bound manual doesn't affect the autonomous build at all. The daemon operates on the wiki and the workbench; the bound manual rebuild is a separate operator-triggered step. Just confirming this is not a blocker.

## What both audits agree on

The single highest-priority mitigation is **building the three missing daemon tools tonight before the 8hr window starts**. Without those, the autonomous ingest does no work, the autonomous page-creation does no work, and the firewall lint is silent. The daemon has been running for hours producing the appearance of work without doing the work the manual claims it does. **Fix this first.**

## Revised execution sequence (incorporating both audits)

1. **Read current daemon state** — recent morning reports, last successful tick, current cell counts.
2. **Verify Marker-converted papers are queued** in `raw/markdown/`.
3. **Build the three missing daemon tools**:
   - `tools/autonomy/create-missing-pages.mjs`
   - `tools/autonomy/firewall-lint.mjs`
   - `tools/autonomy/ingest-marker-batch.mjs`
4. **Define cell-closure tiers** (A, B, C) in a measurement script.
5. **Wire Cat 5 page regeneration** (currently absent).
6. **Run a 10-paper smoke test** through the new ingest tool. Verify it works end-to-end (Marker MD in → wiki/sources/ MD out).
7. **Tune daemon environment** for the 8hr window (env vars, cost ceiling, timeout).
8. **Run `npm run wishlist:gap-driven`** to refresh the wishlist + fetch new PDFs.
9. **Trigger first manual tick** to bootstrap the cycle.
10. **Write the prompt catalog and Warp execution guide**.
11. **Update CLAUDE.md or .claude/ entrypoint** to surface the catalog to future Claude sessions.
12. **Commit + push all 8hr-build artifacts**.
13. **Let the daemon run** for 8 hours autonomously.
14. **Closeout report** at t+8h.

This sequence is what the execution log (03-execution-log.md) will track.
