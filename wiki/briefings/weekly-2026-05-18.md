## Cochrane comparison

### 1. Verdict

**Approaching Cochrane-class.** The methodology layer (locked P97/P45 math, deterministic pooling code, native-basis conversion logged per source, architectural HMT&C firewall, per-claim routing provenance) is at or above Cochrane's typical baseline for transparency and reproducibility — Cochrane reviews are human-mediated and rarely ship the synthesis math as runnable code. Where the wiki falls short is corpus completeness: 968 ingested sources against an identified target of ~23,000 papers (~4%), no PRISMA-style flow diagram, no documented multi-database search strategy, and no per-source risk-of-bias instrument — the exact surfaces a plaintiff's expert would attack first.

### 2. Dimensional grading

- **Corpus completeness — 2/5.** 968 sources ingested out of a ~23k identified corpus; OpenAlex is the only documented retrieval channel; no PRISMA flow diagram; no recorded queries against PubMed, Embase, Web of Science, Scopus, FDA dockets, EFSA opinions, or Codex Alimentarius. Cochrane baseline: 5. EFSA baseline: 4. This wiki is currently below EFSA on this axis, and a hostile reader can demonstrate the gap by naming an obvious paper that is absent.
- **Source provenance — 4/5.** Routing layer enforces per-claim source linkage; lint blocks claims without a `wiki/sources/` backlink; `data/evidence/review_events.jsonl` records each synthesis event with contributing cite-keys. Cochrane baseline: 5. The remaining gap is that synthesis statements on metal and ingredient pages do not always cite source page line ranges — claim → source page, not claim → source page → quoted passage.
- **Methodology transparency — 4/5.** Standards math is locked, versioned (Governing Principles v2.1), and executes in code (`tools/evidence/basis-conversion.mjs`, pooling engine, P97/P45 percentiles, regulatory-cap `min()`). Rationale tags (`literature-baseline`, `regulatory-alignment`, `precautionary`, `feasibility-driven`) are enforced. Cochrane baseline: 4–5. Stronger than Cochrane on machine-reproducibility, weaker because there is no per-source risk-of-bias instrument analogous to RoB 2 / ROBINS-I — `evidence_tier: A/B/C` is one composite where Cochrane uses five named domains.
- **Replicability — 3/5.** Git commits per ingest plus the routing audit make it possible to reconstruct any wiki state at a past date. Full-resynthesis triggers at n_studies doublings prevent permanent drift. The weakness is incremental-update mode (top-5 prior contributors), which is path-dependent: two reviewers starting from different prior states would not necessarily converge on the same `typical_ppb` until a full-resynthesis fires. Cochrane baseline: 4.
- **Currency — 3/5.** Conceptually a living build with continuous ingest. But 23 cells synthesized this week against ~2,450 ingredient×metal cells (245 ingredients × 10 HMTc analytes), and 302 of 367 pools are BLOCKED versus 51 READY (86% blocked). The corpus is current; the synthesis surface is not. Cochrane baseline: 3 (living reviews are still nascent there too, so this is at parity).
- **Independence — 4/5.** Architectural separation between `heavymetalindex.com` and `heavymetaltested.com`; Part 2 of CLAUDE.md enforces drift-direction checks on every substantive edit; HMT&C-certified brands are never named in the wiki; standards arithmetic is explicitly excluded from `wiki/`. Cochrane baseline: 4 (declared COIs, varying funder independence). The residual exposure is that the same operator (Paleo Foundation) runs both — the firewall is real but a hostile reading will still call it "same hand on the scale." The answer to that is the firewall's auditability, which holds.

### 3. Improvement vectors (all targeting corpus completeness — the weakest dimension)

**a. PRISMA-equivalent search strategy + flow diagram generator.** Build `data/evidence/search-strategy.md` with one section per source channel (PubMed, Embase, Web of Science, Scopus, OpenAlex, FDA dockets, EFSA opinions, Codex Alimentarius, WHO/JECFA, grey literature) recording the exact query strings, date of execution, hit counts, and deduplication rules. Add `tools/audit/prisma-flow.mjs` that emits a Mermaid flow diagram per ingest batch into `wiki/methodology/prisma-flow.md`: `Records identified (N) → Duplicates removed (N) → Screened (N) → Excluded with reason (N, categorized) → Full-text assessed (N) → Included (N)`. Wire it into the existing batch-report writer so every ingest batch updates the flow diagram automatically. This is the single artifact that converts "we ingest from OpenAlex" into a defensible search strategy.

**b. Multi-database retrieval pipeline beyond OpenAlex.** Extend the autonomy loop with retrieval workers for PubMed (E-utilities), Web of Science (Lite API), Scopus (Elsevier API), FDA dockets (regulations.gov API), EFSA Journal RSS, and Codex Alimentarius (web scrape with cached HTML). Each worker writes candidate cite-keys into `data/evidence/retrieval-queue.csv` with `source_channel`, `query`, `retrieved_at`. Dedupe against existing `wiki/sources/` by DOI, then PMID, then title-similarity. This raises the denominator from "papers OpenAlex surfaces" to "papers the union of indexed databases surfaces" — the only credible answer to "did you search comprehensively?"

**c. Exclusion ledger with categorized reasons.** Currently a paper either appears in `wiki/sources/` or it doesn't; there is no record of papers screened and rejected. Build `data/evidence/exclusion-ledger.csv` with columns `cite_key | retrieved_from | excluded_at | exclusion_reason | excluded_by`. Reasons drawn from a fixed vocabulary: `out_of_scope_domain` (not food/heavy-metals), `out_of_scope_population` (lab animal only with no human extrapolation), `superseded_by_newer` (with cite-key of superseding paper), `non_english_untranslated`, `retracted`, `methodology_below_C_tier`, `duplicate_of` (with cite-key). Run the exclusion classifier as a Codex pass on retrieval-queue rows that fail to ingest. This converts "absent paper" into "absent paper with a reason on the record" — the hostile-scrutiny check is "name a paper you should have but don't," and the answer becomes a row in the ledger rather than a silent gap.
